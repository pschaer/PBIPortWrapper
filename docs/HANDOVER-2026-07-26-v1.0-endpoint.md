# Handover — v1.0 XMLA endpoint (2026-07-26)

Read this first if resuming. It carries the decisions and the traps; the blow-by-blow
is in the Gitea issues.

## Where things stand

**The original goal is achieved and field-verified.** A remote user, on another machine,
as a different Windows user, queries a Power BI Desktop model over HTTP. That was the E1
barrier, and it is gone. Excel on a second machine completed a full session — ~48
requests, zero faults.

The product is being rebuilt around that, per epic **#124**: one stable HTTP XMLA
endpoint, models addressed by alias, everything else retired.

## The decision this session ends on: per-model paths

**Each model gets its own path on one port** — `http://host:55556/Sample01`.

### Why

"One endpoint, many models" collided with a fact about XMLA: **a session belongs to one
server.** Excel opens a session at connect time — *before* the user picks a database —
so it lands on whichever engine sorts first. Selecting another model then sends that
engine a session it never issued:

```
XMLAnalysisError.0xc10c000a  The '258A6ED0-...' session ID cannot be found.
```

Routing is not the problem: the request reaches the right engine. The session is simply
foreign there.

### Options weighed, and why they lost

- **Session mapping inside the relay** (own the session identity, swap IDs in both
  directions). Works, but requires rewriting session headers in *responses* plus session
  lifecycle, idle timeouts and `EndSession` handling — a permanent complexity commitment
  on a solo-maintained tool, to buy multi-model browsing inside a single connection.
- **Routing at session initiation.** Good instinct, defeated by ordering: the session is
  created before the catalog is known, so there is nothing to route on. It collapses into
  session mapping.
- **A port per model.** Solves sessions identically, but reinstates per-model network
  plumbing — a firewall rule, a URL ACL and a port conflict surface for every model — and
  resurrects `FixedPort`, the concept this simplification exists to remove.
- **Accept the limitation.** One model per connection already works. Rejected as a
  standing state, though it is what ships until the rework lands.

### Why per-model paths is the good answer

Each path is genuinely *one server, one engine*, so sessions work natively and the
problem stops existing rather than being managed. It is **less** code than today: the
fan-out, the catalog merge, the canonical retry and the fan-out session stripping all
disappear — including the only place the relay touches a response.

Alias constraints are near-nil: paths accept percent-encoded spaces, and the alias is
already validated as an SSAS database name. Add "URL-friendly" to that existing
validation, enforced at entry with a clear message.

Nice-to-have, not a priority: the root path as a discovery aid returning a fault that
names the available model URLs.

## The rule that must not erode

**The relay relays; it does not translate.** AMO's `Server.SendXmlaRequest` takes the
client's SOAP envelope verbatim and returns the engine's own response, so msmdsrv
produces every rowset, schema and value.

Precisely stated: **responses are never altered.** Requests are forwarded untouched
except where a connection-scoped detail is meaningless to the target — and after this
rework there is no such case left.

The alternative was tried and abandoned (PR #121, closed): parse the SOAP, call
`GetSchemaDataSet`, re-serialise rowsets with a hand-built XSD. It took 24 commits to
approximate one rowset. If you find yourself editing response XML, that road is growing
back.

## Traps, all of which cost real time

- **Diagnose from `%APPDATA%\PBIPortWrapper\{log.txt,config.json}` first.** Every bug this
  session was found in one log line and lost rounds to guessing beforehand. If a routing
  branch or a failure path logs nothing, that is a defect in its own right — two bugs
  hid in unlogged branches.
- **`Catalog` in a PropertyList is the connection's current database, not a filter.**
  Only `CATALOG_NAME` in a RestrictionList narrows a rowset. They look alike and mean
  opposite things.
- **Catalog names arrive MDX-quoted** — Excel asks for `[Sample02]`. Compare unquoted,
  including `]]` as the escape for a literal bracket.
- **Integrated Windows auth needs a domain.** On a workgroup host the NTLM handshake
  fails inside `HttpListener` before a context exists, so the client gets *no reply* and
  appears to hang. `Basic` (validated against local Windows accounts) is the default.
- **Credentials are never stored.** Every auth mode is a built-in
  `AuthenticationSchemes` value. A custom user store is permanently out of scope.
- **Rebuilding `bin\Debug` does not update a running instance.** When a fix "doesn't
  work", first compare process start time against the build.
- **Do not ship a change flagged as unverified.** Stripping session headers globally was
  shipped with that caveat attached and broke Excel's `BeginSession`. The caveat is not
  the mitigation.

## Disposition

- **PR #123** — merge it. Most of it survives the rework (routing moved into the relay,
  MDX-quoted names, fault logging) and it leaves `develop` strictly better than today:
  both models list, one works end to end. The rework then removes the fan-out.
- **#134** (session affinity) — close unbuilt. Per-model paths make it moot, and the
  pinning it proposed would not have fixed the problem anyway.
- **Config**: `LogPayloads` was switched on for diagnosis. Turn it off — payloads contain
  query results and `log.txt` rotates at 5 MB.

## Next

Per-model paths, then epic #124's sequence: endpoint settings and UI (#125) before
retiring forwarding (#126), because the config file stops being the fallback.

Prove the new world before demolishing the old. `develop` should never be mid-way broken.
